# 🧠 Market Intelligence Agent

> An end-to-end automated system that ingests live financial and business news, runs NLP-powered sentiment analysis, enables natural language querying via a RAG pipeline, and serves insights through an interactive AI agent dashboard - with zero manual intervention.


## 📌 Project Overview

This project was built to demonstrate production-style data engineering and GenAI skills. It goes beyond dashboards — the entire data pipeline runs autonomously on a schedule, data cleaning and enrichment happen in code, and users can query the system in plain English.

**Key capabilities:**
- Ingests 100+ live news articles every 6 hours across 5 market topics
- Automatically cleans, deduplicates, and stores articles in PostgreSQL
- Runs sentiment analysis on every article using DistilBERT (HuggingFace)
- Embeds articles into a vector store (ChromaDB) for semantic search
- Exposes a LangChain ReAct AI agent that reasons over live data
- Serves everything through an auto-refreshing Streamlit dashboard

## 💬 AI Agent Capabilities

The agent uses LangChain's ReAct framework and has access to four tools:

| TOOL | WHAT IT DOES |
|------|--------------|
| `search_articles` | Semantic search over ingested articles using RAG |
| `get_sentiment_summary` | Sentiment stats by category from PostgreSQL |
| `get_top_articles` | Most positive or negative articles by score |
| `get_trending_topics` | Article volume and mood over last N days |

**Example queries:**
- *"What is the sentiment around artificial intelligence this week?"*
- *"Show me the top 5 most negative articles"*
- *"Which category has the most positive news right now?"*
- *"What topics are trending and what's the overall market mood?"*

## 🔑 Key Technical Decisions

**Why Groq instead of OpenAI?**
Groq provides free API access to `llama-3.3-70b-versatile` which is production-grade and handles multi-step ReAct reasoning reliably. Smaller 8B models were tested but failed to follow the ReAct format consistently.

**Why ChromaDB for vectors?**
ChromaDB runs locally with zero setup, no cloud account or API key needed. For a production deployment, this could be swapped for Pinecone or pgvector.

**Why APScheduler instead of Airflow?**
APScheduler runs in-process with no infrastructure overhead, making it ideal for a single-machine deployment. Airflow would be the right choice for a distributed or team environment.

**Why DistilBERT for sentiment?**
DistilBERT is fast, runs locally, requires no API calls, and is accurate enough for financial news classification. It runs once per article and results are cached in PostgreSQL.
